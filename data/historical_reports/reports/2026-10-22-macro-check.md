## 〇-D　🔧 本轮唯一硬产出：FIA 官网访问障碍已定位并绕过

**问题**：本轮起 `curl https://fia.mof.gov.vn/` 直接失败（**exit 6 = 域名解析失败**），`WebFetch` 亦返回 `fetch failed`（`/`、`/vi` 两次），`/Pages/home.aspx` 返回 404。若照此判定，会误报「源失效」。

**根因**（DoH 返回原文）：
```
Status: 2 (SERVFAIL)
Comment: DNSSEC validation failure.
extended_dns_errors: info_code 12 — "Invalid denial of existence of mof.gov.vn/ds"
```
→ **`mof.gov.vn` 的 DNSSEC 委派配置有误**（`mof.gov.vn/ds` 缺失证明无效），**所有做 DNSSEC 校验的解析器一律 SERVFAIL**，域名根本解析不出 A 记录。与本库数据、站点状态无关。

**绕过方法（已验证可用，建议固化为标准动作）**：
```
# 1) 关闭 DNSSEC 校验取 IP（cd=1）
curl -s "https://dns.google/resolve?name=fia.mof.gov.vn&type=A&cd=1"
#    → 182.236.112.202

# 2) 以 --resolve 直连 IP
curl -s --resolve fia.mof.gov.vn:443:182.236.112.202 \
  -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120.0.0.0 Safari/537.36" \
  https://fia.mof.gov.vn/
#    → HTTP 200 / 176,852 B，期次字符串可正常 grep
```
NSO 同法（`www.nso.gov.vn` → `160.25.148.3`）亦通，HTTP 200／118,162 B。

> 意义：此前多轮把 FIA「抓不到」记为「需要首页 grep 期次字符串」，但**本轮证明失败发生在 DNS 层而非站点层**。Cloudflare DNS 另返回 `EDE(3) Stale Answer`，同样指向该域 DNSSEC 异常。
