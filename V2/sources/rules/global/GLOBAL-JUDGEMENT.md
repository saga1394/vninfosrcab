# V2 全局研判规则库 (GLOBAL-JUDGEMENT · Ref: 9381 / 2946)

> 本规则属于 V2 不可覆写全局约束（Immutable Global Policy）。任何底层卡片与上层 Skill 只能引用，不得改写或放宽以下红线。

## 1. 内容层时效锚定与隔离带 (Freshness Anchoring)
1. **HTTP 200 ≠ 内容新鲜**：政府厅局与工业园常青页面常长期返回 200 OK，却展示半年前公文。
2. **48~72 小时增量窗**：每日早报仅纳入明确锚定在近 48~72 小时内的真实新动态。
3. **无锚点隔离 (`date_unverified`)**：列表未提取到明确发布/签发/公示日期的条目，自动标为 `date_unverified` 并移出当日增量候选主池。

## 2. 研判时序纠偏：先事实抽槽，后映射栏目 (Ref: 9381 盲区 1)
严禁按“信源所属部门/地域”机械倒推报告栏目，必须遵守三步顺序：
1. **客观事实抽槽**：抽取主体企业、投资额/面积/产能、物理落位省份/园区、项目生命周期阶段与文号日期；
2. **映射五大正交纯净栏目**（标题严格纯净，严禁加副标题或括号注解）：
   * `fdi` -> `一、 【FDI 外资投资动向】`
   * `industrial_park` -> `二、 【工业园区一线动态】`
   * `industry_focus` -> `三、 【重点关注产业专题】`
   * `legal_approval` -> `四、 【行政审批与法定公示】`
   * `macro_policy` -> `五、 【政经与综合市场动态】`
3. **跨渠道纠偏示例**：地方政府门户发布外资建厂奠基 -> 归 `fdi` 或 `industrial_park`；部委公告半导体/绿电 DPPA 专题进展 -> 归 `industry_focus`；环评/土地规划批复公示 -> 归 `legal_approval`。

## 3. 事件生命周期状态机 (Event Lifecycle)
项目按单调递增阶段追踪，避免重复报喜与阶段倒退：
1. `0: 意向/备忘 (MOU)`
2. `1: 投资立项/获颁投资登记证 (IRC)`
3. `2: 征地拆迁/土地移交 (Site Clearance / Land Grant)`
4. `3: 环评公示/排污与建设许可 (EIA / Permit)`
5. `4: 现场奠基/开工建设 (Groundbreaking)`
6. `5: 封顶/试产/正式投产 (Operating)`
7. `6: 增资扩产/并购/资产转移 (Expansion / Exit)`

## 4. 三档去重规范
* **一档（必须合并）**：多家媒体同日转发同一企业公关通稿或同一事实通告 -> 仅保留高权威原始信源为代表并聚合多个 `Candidate_ID`；
* **二档（可并列补充）**：同事件不同权威切面（如母公司公告金额 + 园区披露占地面积）-> 合并为一条高信息密度简报并挂接全部佐证 `Candidate_ID`；
* **三档（不得去重）**：同一项目跨越至更高生命周期阶段 -> 标记 `is_follow_up=true`，在【事实】中串联过往节点。

## 5. 防幻觉与公休日容错底线
* LLM 研判输出结构受限于 `CuratedBriefItem`，只能引用 `ref_candidate_ids`，严禁输出任何 URL；
* 全部外链经 `backfill_candidate_urls()` + Lazy Probe（仅校验最终入选 Top 条目）物理回填；
* 周末或法定假日若 `legal_approval` 为 0 条，正常输出空仓说明占位，不触发异常熔断。
